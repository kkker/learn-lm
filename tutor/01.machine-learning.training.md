## 1. 訓練完成模型的序列化導出 (Serialization)
在 `main.py` 的訓練流程最尾端，必須將記憶體中的模型物件「序列化」並封裝存檔，以便生產環境的 API 服務能隨時載入執行，不需重新經歷耗時的訓練過程。

### 核心代碼：
```python
import joblib

# 將訓練好的隨機森林模型打包存檔為 pkl 檔
joblib.dump(model, "predictive_maintenance_model.pkl")
print("【成功】AI 模型已成功打包為 predictive_maintenance_model.pkl！")
```

## 2. 安全性重構：Python Flask API 服務 (`app.py`)
傳統隨機森林模型在接收新資料推論時，嚴格要求傳入的 `pd.DataFrame` 欄位順序必須與訓練時（`X_train`）一模一樣。若順序錯置，模型不會報錯，但會將數據張冠李戴導致預測全錯。

本代碼透過 `FEATURE_MAPPING` 字典，強制約束並動態重組傳入的 JSON 欄位，確保推論時的資料結構安全；同時加入 `.item()` 或強轉型邏輯，避免多維陣列產生的 scalar 轉型錯誤。

```python
from flask import Flask, request, jsonify
import pandas as pd
import joblib

app = Flask(__name__)

# 1. 載入序列化模型
model = joblib.load("predictive_maintenance_model.pkl")

# 2. 定義嚴格的欄位映射與物理感測器順序 (防止欄位對調導致預測失準)
FEATURE_MAPPING = {
    'Air temperature [K]': 'air_temp',
    'Process temperature [K]': 'process_temp',
    'Rotational speed [rpm]': 'rpm',
    'Torque [Nm]': 'torque',
    'Tool wear [min]': 'tool_wear'
}

@app.route('/predict', methods=['POST'])
def predict():
    try:
        # 接收來自 Web 端的 JSON 請求
        data = request.get_json()
        
        # 3. 依據 FEATURE_MAPPING 的 Key 順序動態建立字典，保證欄位順序 100% 正確
        ordered_data = {}
        for csv_col, json_key in FEATURE_MAPPING.items():
            ordered_data[csv_col] = float(data[json_key])
            
        # 4. 轉換為 Pandas DataFrame 結構
        input_data = pd.DataFrame([ordered_data])
        
        # 5. 進行 AI 預測
        prediction = model.predict(input_data)
        
        # 6. 除錯與安全修正：將多維陣列/Tensor 結果轉換為 Python 原生純量 int
        # 避免拋出 "only 0-dimensional arrays can be converted to Python scalars" 錯誤
        final_pred = int(prediction)
        
        # 7. 回傳標準 JSON 格式
        return jsonify({
            'status': 'success',
            'machine_failure': final_pred,
            'message': '警告：偵測到潛在故障！請停機檢查。' if final_pred == 1 else '機器運行狀態正常。'
        })
        
    except Exception as e:
        # 於終端機印出詳細錯誤日誌，以便後端除錯
        print(f"【API 內部出錯】: {str(e)}")
        return jsonify({'status': 'error', 'message': str(e)}), 400

if __name__ == '__main__':
    # 監聽 0.0.0.0 埠號 5000，允許 Docker 容器內外通訊
    app.run(host='0.0.0.0', port=5000)
```

**運行指令：**
```bash
python3 app.py
```

## 3. 跨語言整合：PHP cURL 呼叫端 (`predict.php`)
模擬生產線（或前端系統）透過 HTTP POST 通訊協定，將即時採集的感測器數據發送至 Python 微服務，並解析 AI 回傳之預測 JSON 結果。

```php
<?php
// 1. 模擬即時感測器採集數據
$sensor_data = [
    'air_temp'     => 298.1, // 空氣溫度 (K)
    'process_temp' => 308.6, // 製程溫度 (K)
    'rpm'          => 2800,  // 設定異常高轉速 (模擬功率/散熱故障情境)
    'torque'       => 55.0,  // 扭力 (Nm)
    'tool_wear'    => 210    // 刀具已磨損時間 (min)
];

// 2. Python Flask API 在 Docker 內部之通訊位址
$url = 'http://localhost:5000/predict';

// 3. 初始化 cURL 進行 POST 發送
$ch = curl_init($url);
curl_setopt($ch, CURLOPT_POSTFIELDS, json_encode($sensor_data));
curl_setopt($ch, CURLOPT_HTTPHEADER, array('Content-Type:application/json'));
curl_setopt($ch, CURLOPT_RETURNTRANSFER, true);

$response = curl_exec($ch);
curl_close($ch);

// 4. 解析結果 JSON
$result = json_decode($response, true);

echo "========= 🏭 工業產線 AI 預測系統 (PHP 端) =========\n";
if ($result && $result['status'] === 'success') {
    echo "AI 預測結果代碼: " . $result['machine_failure'] . "\n";
    echo "系統提示訊息: " . $result['message'] . "\n";
} else {
    echo "系統錯誤: 無法連線至 AI 預測模組。\n";
}
echo "====================================================\n";
```

**運行指令：**
```bash
php predict.php
```

## 4. 關鍵除錯經驗（Debug Log）

### 🚨 錯誤現象：
當 PHP 發送 cURL 請求後，Python API 終端機彈出 `400` 錯誤，且擷取到例外訊息（Exception）：
`only 0-dimensional arrays can be converted to Python scalars`

### 💡 原因剖析：
由於底層 PyTorch/Scikit-learn 的版本相容性，模型在執行 `.predict()` 進行推論後，回傳的 `prediction` 物件本質上是一個包含多維陣列結構的資料型態（例如包含 NumPy Array 或 Tensor 的元素），而非標準的 Python 數值。
在原始程式碼中直接執行 `int(prediction)` 時，Python 無法直接將內含多重維度陣列的物件轉換成單一純量（Scalar）整數，進而導致 API 崩潰。

### 🛠️ 解決方案：
在執行轉型前，必須確保取出該多維陣列中的單一核心元素值。在 `app.py` 中，將預測結果透過 `int(prediction)` 重新指定或明確使用 `.item()` 函數（如 `prediction.item()`）將其安全攤平成純量，即可順利讓 `jsonify` 打包成整數型態，成功回傳 `200 OK` 訊息。
