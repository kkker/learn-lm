# 機器學習預備練習技術日誌：ONNX 跨平台部署與推論篇

## 1. 為什麼需要將模型轉換為 ONNX 格式？
Python 特有的 `.pkl`（Joblib/Pickle）檔案本質上是 Python 的記憶體物件快照，包含 CPython 底層結構與特定類別定義，因此 PHP 等其他後端語言無法直接載入解析。

**ONNX (Open Neural Network Exchange)** 是跨語言的機器學習模型通用交換格式。將模型存成 `.onnx` 後，即可帶來以下優勢：
* **解耦（Decoupling）**：允許徹底擺脫 Python 環境，讓 PHP 等後端語言能直接透過對應的 Runtime 載入模型並於記憶體內執行推論。
* **效能提升**：ONNX Runtime 通常比原生 Python 載入物件快，記憶體佔用極低，對老舊或資源受限的硬體設備非常友善。

以 predictive_maintenance_model 為例：
```

-rw-r--r-- 1 root root 2995017 Oct  5 03:47 predictive_maintenance_model.pkl
```

## 2. 轉檔觀念釐清：轉檔時參考 `X_train` 是否代表內含訓練資料？
在轉檔函式 `to_onnx(model, X_train)` 中傳入訓練資料集（或測試資料集），**並不代表會把歷史資料寫入模型中**。

### 核心目的：
ONNX 的底層架構屬於**「強型態（Strongly Typed）」**與**「固定維度（Fixed Dimensions）」**。傳入 `X_train` 只是將其作為一個資料的 **「外觀規格表（雛形）」**，讓轉檔工具一邊對照著確認「未來輸入資料的欄位數量（例如 5 個欄位）」與「資料型態（例如 32位元浮點數 `float32`）」，一邊將隨機森林的決策樹邏輯翻譯成 ONNX 的運算節點（Nodes）。一旦規格確認完成，原始資料即會被立刻丟棄，不佔用任何檔案空間。

### 業界常見的優雅寫法（不依賴歷史資料物件）：
若不想回頭黏著訓練期的 `X_train` 物件，可手動使用 NumPy 捏造一個相同維度與型態的虛擬規格（Dummy Data）餵給轉檔引擎：
```python
import numpy as np
from skl2onnx import to_onnx
from skl2onnx.common.data_types import FloatTensorType

# 顯式宣告輸入規格：[任意列數(None), 5 個特徵欄位]，型態為單精度浮點數
initial_type = [('float_input', FloatTensorType([None, 5]))]

# 直接進行跨平台格式轉換
onx = to_onnx(model, initial_types=initial_type)

with open("predictive_maintenance_model.onnx", "wb") as f:
    f.write(onx.SerializeToString())
```

## 3. Python 端的 ONNX 高速推論引擎實作 (`app.py`)
Python 同樣能直接載入 `.onnx` 進行服務。本代碼改用微軟官方維護的 **`onnxruntime`** 引擎替代傳統的 `joblib`，並配合 ONNX 要求的強型態特性，使用 NumPy Array 進行高安全性的矩陣資料對接。

### 依賴套件安裝：
```bash
pip install onnxruntime
```
*(註：若要固定環境，亦可將 `onnx`、`skl2onnx`、`onnxruntime` 寫入 Dockerfile 內之 pip 安裝清單)*

### `app.py`（ONNX 驅動版本）
```python
from flask import Flask, request, jsonify
import pandas as pd
import numpy as np
import onnxruntime as ort

app = Flask(__name__)

# 1. 初始化微軟 ONNX Runtime 執行時期會話 (InferenceSession)
print("正在載入 ONNX 高速推論大腦...")
onnx_path = "predictive_maintenance_model.onnx"
session = ort.InferenceSession(onnx_path)

# 動態取得 ONNX 模型宣告的輸入節點名稱 (預設通常為 'float_input')
input_name = session.get_inputs()[0].name

# 2. 定義嚴格的欄位映射與順序 (約束物理感測器數據輸入順序)
FEATURE_MAPPING = {
    'Air temperature [K]': 'air_temp',
    'Process temperature [K]': 'process_temp',
    'Rotational speed [rpm]': 'rpm',
    'Torque [Nm]': 'torque',
    'Tool wear [min]': 'tool_wear'
}

@app.route('/predict', methods=['POST'])
def predict():
    try:
        data = request.get_json()
        
        # 3. 依據 FEATURE_MAPPING 的 Key 順序動態抽取數據
        raw_features = []
        for csv_col, json_key in FEATURE_MAPPING.items():
            raw_features.append(float(data[json_key]))
            
        # 4. 強型態與結構轉換
        # ONNX 引擎不接受 Pandas DataFrame。需使用 NumPy 包裝成二維矩陣，並強制轉型為 np.float32
        input_data = np.array([raw_features], dtype=np.float32)
        
        # 5. 驅動 ONNX 推論引擎
        # session.run 返回一個陣列結構的輸出列表，我們取第一個輸出結果
        onnx_outputs = session.run(None, {input_name: input_data})
        
        # 6. 安全修正：將推論產出的非 0 維陣列結果轉換為 Python 原生純量整數
        # 防止轉換 JSON 時拋出 "only 0-dimensional arrays can be converted to Python scalars" 的 400 錯誤
        prediction = onnx_outputs[0]
        final_pred = int(prediction[0])
        
        # 7. 回傳標準 JSON 格式至呼叫端
        return jsonify({
            'status': 'success',
            'machine_failure': final_pred,
            'message': '警告：偵測到潛在故障！請停機檢查。' if final_pred == 1 else '機器運行狀態正常。'
        })
        
    except Exception as e:
        print(f"【ONNX API 內部出錯】: {str(e)}")
        return jsonify({'status': 'error', 'message': str(e)}), 400

if __name__ == '__main__':
    app.run(host='0.0.0.0', port=5000)
```
